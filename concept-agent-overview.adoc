= 了解NetApp Console代理
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
您可以通过部署 Console 代理来启用 NetApp Console 功能，轻量级软件组件可在您的本地和云存储系统与 NetApp Console 之间提供安全连接，从而实现高级存储协调和数据服务。



== Console 代理的作用

Console 代理弥合了存储系统和 NetApp Console 之间的网络差距。它将您的基础架构安全地连接到 NetApp API 和 Console，使您可以：

* 从 NetApp Console 发现和监控跨 AWS、Azure、Google Cloud 和本地环境的存储系统。
* 从 NetApp Console 协调存储系统上的存储资源调配和配置任务。
* 启用高级数据保护和优化服务。
* 将云提供商凭据与 Console 代理关联，以安全地跟踪云服务使用情况，并将部署连接到正确的订阅，以实现准确的计费和成本管理。




=== 代理架构

代理使用的轻量级流程具有以下特性：

* 从 NetApp Console SaaS 应用程序中提取或推送数据（标准和受限模式）或纯本地操作（私有模式）
* 发起所有通信—NetApp Console 从不向代理发起出站调用
* 使用标准管理协议连接到存储系统
* 使用 TLS 1.3 与云提供商和 NetApp Console API 进行安全通信




=== 代理可用性和运营要求

Console 代理是 NetApp Console 的关键基础设施。NetApp Console 可以处理短暂的停机，但代理必须保持可操作性和可访问性，以实现不间断的管理和数据服务。您有责任确保：

* 代理保持正常运行
* 代理具有到所需端点的网络连接
* 快速解决基础架构故障
* 代理 VM 会根据 NetApp 建议进行维护和升级




== 何时需要 Console 代理

如果要执行以下操作，则需要部署至少一个 Console 代理：

* 使用受限或专用部署模式（Console 安装在您自己的环境中）。需要其他代理才能启用某些服务。
* 访问高级数据服务（NetApp Backup and Recovery、NetApp Disaster Recovery、NetApp Ransomware Resilience、NetApp Data Classification 等）。
* 管理 Cloud Volumes ONTAP 系统。
* 对本地 ONTAP 集群执行高级管理任务。
* 跟踪许可证、监控存储运行状况并规划生命周期升级。


如果没有代理，您可以执行基本的存储发现并访问一组有限的监控和存储管理功能。但是，大多数企业用例需要一个或多个运营代理。

link:concept-modes.html["了解NetApp Console部署模式"] 了解何时需要代理以及代理启用的功能。



== Console 代理的部署选项

可以在以下位置部署 Console 代理：

* Amazon Web Services（标准、受限或专用模式）
* Microsoft Azure（标准、受限或专用模式）
* Google Cloud（标准、受限或专用模式）
* 在您的场所（标准或私有模式）


您的 Console 部署模式、存储环境和数据主权需求决定了您在何处部署代理。跨环境部署多个代理，以实现组织分离或业务需求。

部署代理后，您可以向 NetApp Console 组织注册该代理，以启用该组织的功能。您可以将多个存储系统和数据服务与单个代理关联，也可以跨环境部署多个代理，以实现组织分离或业务需求。



=== NetApp Console SaaS 应用程序代理（标准模式）

在云或本地部署代理，以连接到云托管的 Console SaaS 应用程序。代理启用高级功能，而 Console UI 仍可从任何地方访问。

使用 SaaS 应用程序（标准模式）时，您可以直接从 Console 安装代理。您可以在 AWS、Azure 或 Google Cloud 中安装，也可以在您自己的 Linux 主机或 VCenter 环境中手动安装。

在本地安装代理时，您可以关联相应的云提供商凭据，以启用计费集成和数据服务。



=== 受限模式下的 NetApp Console 代理

您需要安装一个代理，用户可以从中访问 NetApp Console。启用数据服务和管理存储系统需要额外的代理。

如果您在受限模式下使用 NetApp Console，则可以从云提供商的市场中安装代理，或者通过在云或本地或 VCenter 环境中的自有 Linux 主机上手动安装软件来安装代理。

您需要安装一个代理，用户可以从中访问 NetApp Console。需要其他代理来启用数据服务和管理存储系统。

在本地安装代理时，您可以关联相应的云提供商凭据，以启用计费集成和数据服务。



=== 私有模式下的 NetApp Console 代理（内部或云端，无出站连接）

您需要安装一个代理，用户可以从中访问 NetApp Console。启用数据服务和管理存储系统需要额外的代理。

在数据中心或气隙环境中安装代理。代理与 NetApp API 端点没有连接。所有运营均为本地运营，拥有完全的数据主权和控制权。

您需要安装一个代理，用户可以从中访问 NetApp Console。需要其他代理来启用数据服务和管理存储系统。

在本地安装代理时，您可以关联相应的云提供商凭据，以启用计费集成和数据服务。



=== 在需要时使用多个代理

每个代理独立运行，可以管理多个存储系统和数据服务。在需要时部署多个代理：

* 按存储类型或组织功能隔离
* 满足地理或网络分段要求
