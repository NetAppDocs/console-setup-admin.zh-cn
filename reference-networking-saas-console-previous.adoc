= 3.9.55 及以下版本需要网络访问
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
NetApp Console、 NetApp Console代理和NetApp数据服务需要出站互联网访问才能联系必要的端点。


NOTE: 本主题记录了NetApp Console标准模式 3.9.55 及以下版本所需的网络访问。对于 4.0.0 及更高版本所需的端点，请查看link:reference-networking-saas-console.html["4.0.0 及更高版本所需的端点"]。

您需要为以下内容设置网络访问：

* 以软件即服务 (SaaS) 形式访问NetApp Console的计算机
* 您在本地或云端安装的控制台代理。




== 将您的终端列表更新为 4.0.0 及更高版本的修订列表

从 4.0.0 版本开始，控制台代理需要的端点更少。 4.0.0 之前的现有部署仍然受支持。升级到 4.0.0 或更高版本后，您可以在方便时从允许列表中删除旧端点。

NetApp建议更新防火墙规则以使用修订后的端点列表，该列表更小、更安全且更易于管理。  NetApp消除了对通配符条目的需求，并且代理升级的端点支持所有数据服务。

NetApp建议在防火墙中允许选项 1 端点，因为它们更安全，并禁止选项 2 端点，除非您使用勒索软件恢复或备份和恢复。请注意有关这些端点的以下事项：

* 3.9.47 及更高版本支持选项 1 端点。  3.9.47 之前的版本不支持向后兼容。
* 控制台代理首先启动与选项 2 中的端点的联系。如果这些端点不可访问，它会自动联系选项 1 中的端点。
* 如果将控制台代理与NetApp Backup and Recovery或 Ransomware Resilience 一起使用，则系统不支持选项 1 端点。允许选项 2 端点并不允许选项 1。

== 控制台代理联系的云提供商端点

如果控制台代理部署在您的云提供商中，则它们必须能够访问其他端点。

在安装控制台代理之前启用对云提供商端点的访问。

* link:task-install-agent-aws-console.html#networking-aws-agent["为控制台代理设置 AWS 网络访问"]
* link:task-install-agent-azure-console.html#networking-azure-agent["为控制台代理设置 Azure 网络访问"]
* link:task-install-agent-google-console-gcloud.html#networking-gcp-agent["为控制台代理设置 Google Cloud 网络访问"]


所有版本的云提供商端点都是相同的。



== 控制台代理联系的数据服务端点
