[role="lead"]
确保您的 Console 代理虚拟机已安装补丁、大小合适且运行状况良好，以便代理始终保持正常运行。



[[apply-operating-system-updates-to-agent-hosts]]
== 将操作系统更新应用于代理主机

将安全更新应用于代理主机上的操作系统和相关程序包，以便主机保持安全。

这是您作为客户的责任。Console 代理软件可以自行升级，但它不会升级操作系统或相关软件包。


NOTE: 如果在 vCenter 中使用 OVA 部署了控制台代理，则操作系统是代理映像的一部分。link:task-upgrade-agent.html#upgrade-a-vcenter-deployed-console-agent-using-an-iso["使用 ISO 升级代理"^] 以更新操作系统。

遵循贵公司的操作系统分发标准程序。应用操作系统安全修补程序时，无需停止代理主机服务。

对于未从 OVA 部署的代理，请防止在例行 OS 修补期间升级 Docker 或 Podman，以保持与受支持配置的兼容性。您可以通过在更新期间暂时排除 Docker 或 Podman，或者通过永久配置包管理器以跳过 Docker 或 Podman 更新来实现此目的。

以下是如何排除不同 Linux 发行版的 Docker 或 Podman 更新的示例。有关如何从更新中排除软件包的最新说明，请参阅 Linux 发行版的文档。

.Podman 示例
[source, bash]
----
sudo yum update --exclude=podman
sudo yum upgrade
----
.Docker 示例
[source, bash]
----
sudo apt-mark hold docker-ce docker-ce-cli containerd.io
sudo apt update
sudo apt upgrade
----


[[resize-the-vm-or-instance-type]]
== 调整 VM 或实例类型的大小

增加配置不足的代理虚拟机的 CPU 或 RAM，以便代理保持良好的性能。

如果您从 Console 创建 Console 代理，它将使用默认配置在您的云提供商中部署虚拟机实例。link:reference-agent-default-config.html["详细了解代理的默认设置"]。创建代理后，请勿切换到 CPU 或 RAM 较小的虚拟机实例。

如果收到代理 VM 配置不足的通知，请考虑升级到具有更多 CPU 或 RAM 的更大 VM 实例。


NOTE: 如果在 vCenter 中安装了代理，请使用控制台维护工具调整 VM 实例的大小。link:task-agent-vm-config.html["了解如何在 vCenter 中调整代理虚拟机的大小"^]。

如果需要增加代理 VM 的 CPU 或 RAM，请按照云提供商或本地虚拟化平台提供的说明调整 VM 实例的大小。NetApp 建议将当前 CPU 和 RAM 分配增加一倍，以确保最佳性能。下表显示了推荐的大小层级，每个层级的 CPU 和 RAM 是上一层级的两倍。

[cols="1,1,1"]
|===
| 层 | CPU（内核或 vCPU） | RAM 


| 最低 | 8 | 32 GB 


| 中 | 16 | 64 GB 


| 大型 | 32 | 128 GB 
|===

== 监控代理

随时了解代理虚拟机上的磁盘空间、 RAM 和 CPU 问题，以便解决这些问题。

当代理虚拟机不健康时，控制台会通知您，包括磁盘空间、RAM 和 CPU 问题。在控制台内的通知中心监控这些通知或配置电子邮件通知。磁盘空间、内存或 CPU 使用率偶尔增加是正常现象，但如果经常发生，则应采取措施解决。

例如，当代理资源（CPU、RAM 或磁盘空间）连续 30 分钟超过其总容量的 90% 时，控制台会通知您。之后，如果资源使用率低于该阈值，则通知中心将显示通知已解决（绿色）。


NOTE: 如果您对修改代理虚拟机有疑问，请与 NetApp 支持团队合作。

[[stop-and-start-the-agent-vm]]
== 停止并启动代理 VM

停止并启动代理虚拟机时，请限制停机时间，因为管理和数据服务依赖于代理保持运行。

如果需要，请使用云提供商的控制台或标准内部部署程序停止并启动代理虚拟机。

link:concept-agents.html#agents-must-be-operational-at-all-times["请注意，控制台代理必须始终处于运行状态"] 。



[[connect-to-the-linux-vm]]
[[connect-linux-host]]
== 连接到 Linux VM

从其 Linux 虚拟机检查 Console 代理的状态，以便确认其是否正在运行。

如果您需要连接到代理运行的 Linux VM，请使用云提供商提供的连接选项。

AWS:: 在 AWS 中创建代理实例时，请提供 AWS 访问密钥和密钥。您可以使用此密钥对通过 SSH 连接到实例。对 EC2 Linux 实例使用用户名“ubuntu”。对于 2023 年 5 月之前创建的代理，请使用用户名“ec2-user”。
+
--
https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AccessingInstances.html["AWS 文档：连接到您的 Linux 实例"^]

--
Azure:: 在 Azure 中创建代理 VM 时，您可以指定用户名并选择使用密码或 SSH 公钥进行身份验证。使用您选择的身份验证方法连接到虚拟机。
+
--
https://docs.microsoft.com/en-us/azure/virtual-machines/linux/mac-create-ssh-keys#ssh-into-your-vm["Azure 文档：通过 SSH 进入您的 VM"^]

--
Google Cloud:: 在 Google Cloud 中创建代理时，您无法指定身份验证方法。但是，您可以使用 Google Cloud Console 或 Google Cloud CLI (gcloud) 连接到 Linux VM 实例。
+
--
https://cloud.google.com/compute/docs/instances/connecting-to-instance["Google Cloud Docs：连接到 Linux 虚拟机"^]

--
