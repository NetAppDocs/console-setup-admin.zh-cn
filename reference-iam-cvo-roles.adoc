= Cloud Volumes ONTAP 访问角色（位于 NetApp Console 中）
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
您可以将以下角色分配给用户，以便为他们提供对控制台中 Cloud Volumes ONTAP 的访问权限。Cloud Volumes ONTAP 角色使您可以灵活地为用户分配特定于他们需要在组织内完成的任务的角色。如何分配角色取决于您自己的业务和存储管理实践。

Cloud Volumes ONTAP 使用以下角色：

* *Cloud Volumes ONTAP admin*：提供对所有 Cloud Volumes ONTAP 操作的完全访问权限。
* *Cloud Volumes ONTAP operator*：执行重要的存储操作，例如发现和管理 Cloud Volumes ONTAP 系统，包括添加卷、聚合、快照和复制、修改某些配置以及升级 Cloud Volumes ONTAP 版本。
* *Cloud Volumes ONTAP viewer*：提供对 Cloud Volumes ONTAP 信息的只读访问。此角色无法执行任何活动操作。某些包含配置信息的选项卡和屏幕可能无法供查看者使用。


有关所有 NetApp Console 访问角色的详细信息，请参见 link:reference-iam-predefined-roles.html["访问角色"]。



[[how-role-changes-take-effect]]
== 角色变更如何生效

Cloud Volumes ONTAP 通过使用每个角色分配的本地缓存来实施基于角色的访问控制 (RBAC)。此缓存每小时自动刷新一次。如果是新分配或更改的角色，此更改最多可能需要一个小时才能生效。刷新完成后，控制台将启用该角色允许的工作流。


NOTE: 首次部署控制台代理或将现有控制台代理升级到 Console 4.9.0 或更高版本时，控制台将运行一次性种子设定过程，将 Cloud Volumes ONTAP 角色分配给组织中的现有用户。此过程最多可能需要 30 分钟才能完成。
